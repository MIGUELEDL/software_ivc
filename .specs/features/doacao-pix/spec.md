# Doação PIX Specification

## Problem Statement

A árvore oficial prevê **Doação/Oferta (QR PIX público)** (RF-007, RN-001), mas a rota
`/doacao` ainda não existe. A **chave PIX oficial** é o CNPJ **68.683.917/0001-71**
(informado pelo administrador em 2026-09-08 — mesmo CNPJ de ADR-011). Sem lib de QR
instalada no repo. O financeiro com webhook Mercado Pago (RF-026, RN-001.1) fica na
onda 3 — a doação pública é **QR PIX estático** (AD-009), sem cartão no portal (RN-001).

## Goals

- [ ] Rota pública `/doacao` (RF-007) exibindo QR PIX oficial para doação/oferta
- [ ] QR **gerado no app** a partir de uma chave PIX em `src/lib/pix.ts` + constantes (AD-008/RNF-011)
- [ ] Código **PIX copia-e-cola** (BR Code estático) exibido com botão "Copiar"
- [ ] **QR estático sem valor** (o app bancário do doador define o valor ao escanear); sem cartão (RN-001)
- [ ] Acesso via navbar/footer (`/doacao`)
- [ ] Acessibilidade WCAG 2.1 AA (RNF-012) e mobile-first (RNF-001)
- [ ] Nenhuma regressão de build/typecheck/lint (gate verde)

## Out of Scope

| Feature | Reason |
| ------- | ------ |
| Financeiro com webhook Mercado Pago (RF-026, RN-001.1) | Onda 3 — painel admin; credenciais MP em aberto (AD-009, R-003) |
| Doações por cartão no portal | RN-001: portal é **QR PIX apenas** |
| Campo de valor + QR dinâmico por visita | Árvore prevê só "QR PIX público"; QR estático decidido com o admin |
| Painel membro (QR de dízimo pessoal, RF-013) | Onda 2 — painel membro |
| Configuração da chave via painel (RF-029) | Onda 3 — admin |

## User Stories

### US-01: Doação via QR PIX ⭐ MVP

**User Story**: As a visitante que quer contribuir, I want to open `/doacao` and see the
church PIX QR code, so that eu possa doar escaneando o QR com meu app bancário
(RF-007, RN-001).

**Why MVP**: RF-007 é requisito aprovado; doação é fluxo central do portal (funil visível
no OBSERVABILITY.md).

**Acceptance Criteria** (cada linha é um padrão EARS):

1. The system SHALL render the route `/doacao` presenting a QR PIX generated by the app for the church key
2. The system SHALL generate the QR from `PIX.key` (CNPJ `68.683.917/0001-71` → `68683917000171` no payload, sem formatação) via a payload built in `src/lib/pix.ts`, decoding a valid BR Code (copia-e-cola)
3. The system SHALL render the full copia-e-cola payload (BR Code) as text below the QR
4. WHILE a visitor activates the copy button THEN the system SHALL copy the payload to the clipboard and SHALL render a confirmation message to the visitor
5. The system SHALL keep the QR and payload free of a fixed amount (the payer's banking app defines the value)

### US-02: Origem e acesso

**User Story**: As a visitante, I want the donation route reachable from the site nav,
with data coming from the single source, so that eu não precise digitar a URL e os
dados estejam sempre corretos.

**Why MVP**: RNF-011 (fonte única) e acesso visível — mesmo padrão de eventos.

**Acceptance Criteria** (cada linha é um padrão EARS):

6. The system SHALL source `PIX.key` from `src/lib/constants.ts` with no hardcoded institutional literals in components
7. The system SHALL render a "Doação" navigation item linking to `/doacao` in the navbar and footer
8. The system SHALL make every interactive element on `/doacao` accessible via keyboard with an accessible name (WCAG 2.1 AA — RNF-012)
9. The system SHALL render `/doacao` responsively for small screens (mobile-first — RNF-001)
10. The system SHALL pass `npm run lint`, `npm run typecheck` and `npm run build` (green gate)

**Independent Test**: `npm run lint && npm run typecheck && npm run build` + inspeção
estática por AC com `file:line`; decodificar o BR Code `/^000201...6304[0-9A-F]{4}$/` e
verificar a chave `68683917000171` (CNPJ **sem formatação**, 14 dígitos — Manual de
Padrões para Iniciação do PIX/BCB) no MAI; conferir o estado do clipboard no botão
"Copiar" (evidência estática de `navigator.clipboard.writeText`); nenhum literal
institucional nos componentes; navegação com `/doacao` no `NAV_ITEMS`.

## Edge Cases

- IF the copy action fails (clipboard not available/denied) THEN the system SHALL show a fallback message without throwing
- IF `PIX.key` is empty THEN `/doacao` SHALL render a "em breve" message instead of a broken QR
